🌐 GitHub Pages (앱)

  • HTML/CSS/JS 정적 파일 서비스
  • 운영자가 GitHub 저장소만 관리
  • 앱 업데이트 시 모든 사용자 자동 반영
  • 무료 · HTTPS 기본 제공

🔐 Google OAuth 2.0 (로그인)

  • 구글 계정으로 1클릭 로그인
  • Google Cloud에 앱 등록 (무료)
  • Drive 접근 권한 요청
  • 운영자 비용 없음

📁 Google Drive API (데이터)

  • db.json → 구역·항목·BOM 모든 데이터
  • images/ → 평면도 이미지
  • 개인 Drive 15GB에서 사용
  • Google이 자동 동기화 처리

💰 비용 구조

  • 운영자: Google Cloud API 등록 (무료)
  • 개인: 본인 Google Drive 용량 사용
  • 헤비유저: 본인 Drive 용량만 증가
  • 운영자 추가 비용 발생 없음

API 대체 목록 (server.js → Google Drive)

모든 데이터는 개인 Drive의 SmartApt/db.json 한 파일에 저장됩니다. 읽기: Drive에서 db.json 다운로드 → 메모리에서 처리. 쓰기: 메모리에서 수정 → Drive에 db.json 업로드.
현재 서버 API Drive 저장 위치 대체 방식
GET/api/bom-tree SmartApt/db.json
→ items, bom 키		 db.json 다운로드 → 트리 조합 반환
GET/api/zones SmartApt/db.json
→ items 키		 node_type='Z' 필터
GET/api/categories SmartApt/db.json
→ categories 키		 categories 배열 반환
POST/api/zones SmartApt/db.json db 읽기 → items/bom 추가 → db 저장
PUT/api/zones/:id SmartApt/db.json db 읽기 → id 찾아 수정 → db 저장
DELETE/api/bom/:id SmartApt/db.json db 읽기 → 재귀 삭제 → db 저장
POST/api/items SmartApt/db.json db 읽기 → items/bom 추가 → db 저장
PUT/api/items/:id SmartApt/db.json db 읽기 → 수정 → db 저장
GET/api/floorplans SmartApt/db.json
→ floorplans 키		 floorplans 배열 반환
POST/api/floorplans SmartApt/db.json
SmartApt/images/		 이미지→Drive images/ 업로드
메타→db.json floorplans에 추가
DELETE/api/floorplans/:id SmartApt/db.json
SmartApt/images/		 db에서 제거 + Drive 이미지 파일 삭제
GET/api/floorplans/:id/zones SmartApt/db.json
→ fpZones 키		 fp_id 필터해서 반환
POST/api/fp-zones SmartApt/db.json fpZones 배열에 추가 → db 저장
PUT/api/fp-zones/:id SmartApt/db.json id 찾아 수정 → db 저장
DELETE/api/fp-zones/:id SmartApt/db.json id 찾아 삭제 → db 저장

db.json 구조 (개인 Drive에 저장되는 파일)

{
  "nextId": 1050, ← 자동 증가 ID
  "items": [ ← 집(H) · 구역(Z) · 항목(I) 모든 노드
    { "item_id": 1, "node_type": "H", "item_name": "우리집", ... },
    { "item_id": 2, "node_type": "Z", "item_name": "거실", ... },
    { "item_id": 3, "node_type": "I", "item_name": "소파", ... }
  ],
  "bom": [ ← 부모-자식 관계
    { "bom_id": 1, "parent_item_id": 1, "child_item_id": 2, ... }
  ],
  "categories": [ ... ], ← 카테고리
  "floorplans": [ ... ], ← 도면 목록 (이미지 경로 포함)
  "fpZones": [ ... ] ← 도면 위 영역 좌표
}

구현 순서

1

Google Cloud 앱 등록 (운영자 1회)

console.cloud.google.com → 새 프로젝트 → Google Drive API 활성화 → OAuth 2.0 클라이언트 ID 발급
발급된 Client ID를 코드에 설정

2

google-auth.js 작성

Google Identity Services 로그인/로그아웃, 액세스 토큰 관리
파일: public/js/google-auth.js

3

drive.js 작성

Drive API로 SmartApt/ 폴더 생성, db.json 읽기/쓰기, 이미지 업로드/삭제
파일: public/js/drive.js

4

api-local.js 작성 (fetch 인터셉터)

window.fetch 오버라이드 → /api/* 요청을 drive.js 호출로 대체. 기존 HTML 무수정
파일: public/js/api-local.js

5

index.html 수정 (로그인 UI)

비로그인 시 구글 로그인 화면 표시, 로그인 후 앱 진입. SDK 로드 추가
파일: public/index.html

6

GitHub Pages 배포

git push → 자동 배포. .nojekyll 추가로 한글 파일명 인식
Google Cloud 콘솔에 GitHub Pages 도메인 허용 등록 필요

7

장단점

✅ 장점

  • 운영자 비용 완전 없음
  • 데이터 소유권이 완전히 개인에게
  • 구글 계정으로 PC·폰·다른PC 동기화
  • 헤비유저가 생겨도 운영자 무관
  • 개인 Drive에서 db.json 직접 확인·백업 가능
  • Drive API 무료 한도 사실상 무제한

⚠️ 제약

  • 구글 계정 필수
  • 인터넷 연결 필요
  • Drive API 구현이 Firebase보다 코드량 많음
  • 최초 로그인 시 Drive 권한 동의 필요
  • Google Cloud 앱 검수 필요
    (미검수 시 "확인되지 않은 앱" 경고 — 개인 사용 무관)
