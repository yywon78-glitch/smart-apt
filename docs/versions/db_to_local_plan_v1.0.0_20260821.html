Smart Apt — DB 없이 서비스하기

MSSQL Express 서버 → GitHub Pages 정적 서비스 전환 구축 방안
GitHub Pages 호환 서버 불필요 HTML 5개 무수정
1

핵심 아이디어 — Fetch 인터셉터 패턴

기존 HTML 파일 5개를 전혀 수정하지 않는다
fetch('/api/bom-tree')
→
인터셉터가 가로챔
→
localStorage 응답

index.html에 api-local.js 한 줄만 추가하면, 기존 HTML들이 /api/*를 호출할 때 인터셉터가 가로채 DB 대신 브라우저 저장소에서 읽고 씁니다. 서버도 필요 없고, 기존 화면 코드도 건드리지 않아도 됩니다.

API 대체 목록

현재 서버 API 로컬 대체 방식
GET/api/bom-tree localStorage items + bom 조합해서 트리 구성
GET/api/zones localStorage items에서 node_type='Z' 필터
GET/api/categories localStorage cats (seed.js로 초기값 제공)
GET/api/cost 로컬 트리 순회해서 구역별 금액 집계
POST/api/zones next_id++ 로 ID 발급, items + bom에 추가
PUT/api/zones/:id localStorage items에서 id 찾아 수정
DELETE/api/bom/:id bom + items 재귀 삭제 (고아 제거)
POST/api/items next_id++ 발급, items + bom 추가
PUT/api/items/:id localStorage items에서 수정
GET/api/floorplans localStorage fps 읽기
POST/api/floorplans 메타→localStorage, 이미지→IndexedDB
DELETE/api/floorplans/:id fps + fp_zones + IndexedDB 이미지 삭제
GET/api/floorplans/:id/zones localStorage fp_zones에서 fp_id 필터
POST/api/floorplans/:id/zones fp_zones에 추가
PUT/api/fp-zones/:id fp_zones에서 id 찾아 수정
DELETE/api/fp-zones/:id fp_zones에서 삭제

구현 순서

1

storage.js 작성

localStorage / IndexedDB 읽기·쓰기 래퍼. ID 자동 채번, 데이터 직렬화 담당.
파일: public/js/storage.js

2

seed.js 작성

최초 실행 시 "우리집(H노드)" + 기본 카테고리를 localStorage에 생성.
파일: public/js/seed.js

3

api-local.js 작성

window.fetch를 오버라이드해서 /api/* 요청을 가로채 storage.js로 처리. 위 API 16개를 전부 구현.
파일: public/js/api-local.js

4

index.html 수정 (1줄)

<script src="/js/api-local.js"></script> 한 줄을 <head> 안에 추가.
파일: public/index.html

5

내보내기 / 가져오기 기능

대시보드에 백업(JSON 다운로드)·복원(JSON 업로드) 버튼 추가. 기기 간 이전 가능.
파일: public/pages/대시보드.html

6

장단점

✅ 장점

  • 서버 없이 GitHub Pages에서 즉시 서비스
  • 기존 HTML 5개 코드 수정 불필요
  • 인터넷 없어도 동작 (오프라인 가능)
  • 설치·설정 없이 브라우저만으로 사용
  • IndexedDB로 이미지도 넉넉히 저장

⚠️ 제약

  • 데이터가 브라우저에 저장 → 기기마다 별도
  • 브라우저 캐시 지우면 데이터 사라짐
    → 내보내기로 백업 필수
  • 여러 사람 공유 불가 (단일 사용자 앱)
  • 실시간 동기화 없음
