🌐 GitHub Pages (앱 호스팅)

  • HTML/CSS/JS 정적 파일 서비스
  • 앱 업데이트 시 자동 반영
  • 무료 · HTTPS 기본 제공
  • 서버 관리 불필요

🔐 Firebase Auth (로그인)

  • 구글 계정으로 1클릭 로그인
  • 개인별 고유 UID 발급
  • 세션 자동 유지
  • 무료 (제한 없음)

🗄 Firestore DB (데이터)

  • 구역·항목·BOM 등 모든 데이터
  • /users/{uid}/ 경로로 개인 분리
  • 실시간 동기화
  • 무료: 50K 읽기 / 20K 쓰기 / 일

🖼 Firebase Storage (이미지)

  • 평면도 이미지 저장
  • /users/{uid}/images/ 개인 분리
  • URL로 캔버스에 직접 표시
  • 무료: 5GB 저장 / 1GB 전송

구현 순서

1

Firebase 프로젝트 생성 (콘솔)

console.firebase.google.com → 새 프로젝트 → Auth·Firestore·Storage 활성화
웹 앱 설정 값(apiKey 등) 복사

2

firebase.js + auth.js 작성

Firebase 초기화, 구글 로그인/로그아웃, 현재 사용자 UID 관리
파일: public/js/firebase.js public/js/auth.js

3

api-local.js 작성 (fetch 인터셉터)

window.fetch 오버라이드 → /api/* 요청을 Firestore 호출로 대체
파일: public/js/api-local.js

4

index.html 수정 (로그인 UI + SDK 로드)

Firebase SDK CDN 추가, 로그인 화면 추가 (비로그인 시 앱 진입 차단)
파일: public/index.html

5

Firestore Security Rules 설정

allow read, write: if request.auth.uid == userId;
본인 데이터만 접근 가능하도록 규칙 적용

6

GitHub Pages 배포 + .nojekyll 추가

git push → GitHub Pages 자동 배포. 한글 파일명을 위해 .nojekyll 필수
파일: .nojekyll

6

장단점

✅ 장점

  • 구글 계정 하나로 PC·폰·다른PC 동기화
  • 개인별 데이터 완전 분리·보안
  • 서버 운영 비용 없음 (무료 플랜으로 충분)
  • GitHub Pages로 항상 최신 앱 유지
  • 기존 HTML 5개 코드 수정 불필요
  • 실시간 동기화 (여러 기기 동시 사용 가능)

⚠️ 제약

  • 인터넷 연결 필요
  • 구글 계정 필수
  • Firebase 무료 한도 초과 시 과금
    → 개인 사용 수준에서는 무료로 충분
  • Firebase 의존성 발생
